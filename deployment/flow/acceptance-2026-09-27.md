## 实施中修复

- 授权经销商、积分商城的 Dockerfile 在子目录；Flow 构建上下文改为仓库根目录，三条定义已通过云效 API 回读。授权经销商第一次构建因上下文错误失败，修正后第二次成功。
- 长分支的云效源码元数据包含提交历史。构建证据现在只把首条检出 HEAD 与本次 ACR tag 配对，仍要求唯一匹配的 digest；新增复用已完成构建运行号的入口，避免本地核验失败时重新构建。
- Java 多模块首次构建依赖解析较慢，STOPMP 耗时约 50 分钟。Java 菜单的本地等待上限设为 7200 秒；云端构建仍由 Flow 自身运行。
- M1X API 首次构建的 Maven 阶段耗时约 62 分钟并成功，但随后 ACR 推送返回 `401 Unauthorized`。第二次构建仅在 Flow 临时 Dockerfile 中为 Maven Central 配置阿里云公共镜像，约 2 分钟完成构建与推送，固定 digest 上线成功。首次故障与长时间构建后的推送凭据失效相符，但未取得凭据有效期的直接证据。
- 本机菜单的状态命令移到 GUI 所读取的 `targets.prod.status_commands`；配置同步后 GUI 与命令行采用同一配置。
