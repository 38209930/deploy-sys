现阶段只读云 API、ACS 元数据、已有监控/日志的脱敏查询和文档整理可做。读取生产 Secret 值、生产数据库写入、发送真实短信或资金请求、修改生产 Deployment/Ingress/共享网络/监控规则、启用付费 SLS 日志等，须依对象、环境、动作和范围取得明确授权。不要把收到本任务书视作对所有写操作的一揽子授权。证据不足时写“待证据”，不要据代码路径、TCP 建连或 Pod Ready 推断业务已验收。

### 经授权后的单项目执行模板

通过 Kubernetes API 仅修改该 Deployment 的 `spec.template.metadata.annotations["network.alibabacloud.com/vswitch-ids"]`，目标为已在集群配置中的新 vSwitch；保持镜像、配置、副本、Ingress、Service、NAT/SNAT/路由表不变。一次只迁一个 Deployment，等新 Pod Ready、旧 Pod 退出及业务状态明确后再下一个。核对新 Pod IP 属于目标 `/24`、公网出站来源为固定 EIP、MySQL/Redis/Mongo/SmsCore 私网可用、真实业务 SDK 的低风险调用或已有脱敏外呼结果、ALB 对应正式 Host、错误率及 Worker 调度。`curl` 到公网 IP 只能证明网络层，不能代替供应商鉴权和业务结果。

## D. 告警渠道与规则

1. 只读盘点现有云监控/ALB/NAT/EIP/ACS 规则、联系人、通知方式、是否启用及最近告警投递。明确一个主接收人、替补、工作时间与非工作时间路径、超时升级方式和业务事故通知人；联系人信息不写入仓库。
2. 按现有[值班手册](ops-playbook-2026-09-27.md)和实际 CMS 能力提交**可实施规则表**：ALB 5XX（候选：5 分钟错误率 >2% 且请求数 >100，或 5XX 数 >20）；NAT 端口分配失败 >0；EIP 10 Mbps 上限下 5 分钟 >7 Mbps 预警、>8.5 Mbps 且有业务失败升级；Pod 非 Ready 5 分钟或重启数增加；内存使用/limit >80% 持续 15 分钟；售后 Worker 到期未完成、失败队列增加；支付待确认与短信失败由业务状态报警。阈值是待确认初值，核实指标单位、统计周期、维度和平台是否支持复合条件；不支持时拆成可实现的规则并记录误报控制。
3. 给出每条规则的资源 ID、指标、条件、接收组、严重级别、静默/恢复通知、值班处置入口和预期费用。若涉及新增付费日志/监控或扩大通知权限，明确列出并先获授权。不得为测试故意制造生产 5XX、断网、Pod 失败或资金异常。
4. 在联系人及规则写入授权后，通过 API 创建或修改**本次指定**的规则，读回并进行无业务副作用的触达测试；实际发送至人/群的通知需得到接收渠道所有人的明确同意。记录测试发送时间、接收确认、失败原因和修复结果。没有接收人或触达未证实，D 项不通过，C 项不得进入首次生产迁移。

## 统一交付格式与停手条件

工程师提交一份脱敏执行报告和必要的变更单，逐项列 `结论：通过/待证据/阻断/待授权`、查询时点、证据来源、RequestId 或 Kubernetes 资源版本、与历史基线差异、下一步责任人。更新[验收整改记录](acceptance-remediation-2026-09-27.md)、[值班手册](ops-playbook-2026-09-27.md)和[值班日志](duty-log.md)中实际改变的结论；历史快照不涂改。文档变更按仓库规则提交并推送任务分支，核对远端状态。

遇到账号不符、真实配置/密码可能外泄、未确认的第三方白名单、旧短信直连仍生效、Worker 重复执行风险、共享网络差异、生产业务结果不明或授权缺失，立即停止相关**写操作**，保存只读证据并报主公；可继续其他独立的只读工作。不要靠临时改架构、放宽网段或触发真实交易来绕过阻断。
